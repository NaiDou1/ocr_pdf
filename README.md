# 拍照转 PDF（ocr_pdf）

**把手机拍的文档照片，自动转正、压缩、按拍摄顺序打包成一个 PDF。**

竖着拍的、横着拍的、拍倒了的一律不用管——脚本会调用 Windows 系统自带的 OCR 引擎，
逐张判断照片到底该往哪边转，然后转成黑白压缩打包。你只管拍，剩下的交给它。

> 实测效果：一批 59 张手机照片（102.1 MB）→ 13.1 MB 的 PDF，体积压到 **13%**，
> 文字依然清晰可读。

---

## 它解决什么问题

手机拍书上的题、讲义、试卷，攒多了就会变成一堆麻烦：顺序乱的、横竖混着的、
拍倒了的、一张两三兆的。想做成一个能翻的 PDF，手工处理要折腾半天。

这个脚本把整个流程压成一条命令：

| 手工做法 | 本脚本 |
| --- | --- |
| 一张张看哪张拍反了，手动旋转 | 系统 OCR 自动判方向，逐张处理 |
| 按文件名或者记忆手动排序 | 按拍摄时间（EXIF 文件名）自动排序 |
| 用画图/PS 压缩，或者干脆不压 | 转灰度 + 自动对比度 + JPEG 压缩 |
| 找在线工具合成 PDF（还要上传） | 本地命令行一条命令搞定，全程离线 |
| 合成后顺序又乱了，重新来一遍 | 可重复运行，结果稳定 |

**核心难点是方向判断。** 很多人以为"横版照片统一顺时针转 90° 就行"，实际不是：
拍摄时手没拿稳，同一个人的横版照片可能有的要顺时针、有的要逆时针；竖版照片也可能
整个 180° 倒过来。在真实的一批 34 张照片上实测：

| 照片类型 | 张数 | 需要的处理 |
| --- | --- | --- |
| 横版 | 1 | 顺时针 90° |
| 横版 | 9 | **逆时针 90°** |
| 竖版 | 6 | **旋转 180°** |
| 竖版 | 18 | 保持原样 |

也就是说，任何**固定方向**的方案在这批照片上都必然错一大半。本脚本对每张照片
单独判断方向，这才是它和"批量旋转工具"的本质区别。

## 环境要求

- **Windows 10 / 11**（自动判方向依赖系统 OCR；其它系统见下方"非 Windows"说明）
- **Python 3.9+**
- 中文识别需要系统装有**简体中文 OCR 语言包**。国行 Windows 通常自带；
  若提示 OCR 不可用，去「设置 → 时间和语言 → 语言和区域」给中文补上
  「可选语言功能 → 光学字符识别」

依赖只有两个：`pillow` 用于图片处理，`winrt-*` 用于调用系统 OCR。
**首次运行时脚本会自动帮你装，不用手动 pip。**

## 快速开始

### 方式一：双击运行（推荐）

1. 把 `ocr_pdf.py` 和 `一键生成PDF.bat` 放进**有照片的那个文件夹**
2. 双击 `一键生成PDF.bat`
3. 等它跑完，同目录下会出现 `<文件夹名>.pdf`

首次运行会花一两分钟自动安装依赖。窗口里会实时显示每张照片被转了多少度。

### 方式二：命令行

```bash
# 处理当前目录，输出 <目录名>.pdf
python ocr_pdf.py

# 指定照片目录
python ocr_pdf.py D:\photos\数电课后作业

# 指定输出文件名
python ocr_pdf.py D:\photos\数电课后作业 -o 数电作业.pdf

# 递归处理子目录，并且压得更狠一点
python ocr_pdf.py D:\photos -r --max-long 1800 -q 65

# 查看每张图四个方向的 OCR 得分（排查判错时很有用）
python ocr_pdf.py D:\photos --show-rotation-scores
```

### 手动安装依赖

如果自动安装被网络或权限挡住：

```bash
pip install pillow
pip install winrt-runtime winrt-Windows.Foundation winrt-Windows.Foundation.Collections \
            winrt-Windows.Media.Ocr winrt-Windows.Graphics.Imaging \
            winrt-Windows.Storage winrt-Windows.Storage.Streams winrt-Windows.Globalization
```

## 参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `folder` | `.` | 照片所在目录 |
| `-o, --output` | `<目录名>.pdf` | 输出 PDF 路径 |
| `-r, --recursive` | 关 | 递归处理子目录 |
| `--no-detect-rotation` | 关 | 关闭 OCR 自动判方向，用固定方向 |
| `--rotate-ccw` | `cw` | 关闭自动判方向后，横版照片统一转的方向，可选 `cw` / `ccw` / `none` |
| `--ocr-lang` | `zh-Hans-CN` | OCR 识别语言 |
| `--show-rotation-scores` | 关 | 打印每张图各方向的 OCR 分数 |
| `-q, --quality` | `72` | JPEG 质量，1–95 |
| `--max-long` | `2200` | 长边最大像素，超出等比缩小；`0` = 不缩放 |
| `--bw` | 关 | 输出纯黑白二值图，体积最小（公式可能略糊） |
| `--no-auto-contrast` | 关 | 不做自动对比度增强 |
| `--portrait-all` | 关 | 连竖版照片也转成横躺，让每页方向统一 |
| `--keep-temp` | 关 | 保留中间 JPEG 到 `_pdf_pages/` |
| `--quiet` | 关 | 不打印每页进度 |

### 常用调节

```bash
# 字太小 / 想更清楚
python ocr_pdf.py --max-long 2800 -q 80

# 只想让文件尽可能小（纯黑白二值）
python ocr_pdf.py --bw --max-long 1800 -q 60

# 某批照片自动判方向判错了，改用固定方向
python ocr_pdf.py --no-detect-rotation --rotate-ccw ccw
```

## 自动判方向是怎么做的

1. **四个方向各 OCR 一遍**：原样、顺时针 90°、逆时针 90°、旋转 180°
2. **给每个结果打分**：汉字权重 2、字母数字权重 1，累加求和
   （文字方向对了，OCR 才能读出通顺的句子，分数会明显高出一截）
3. **取分最高的方向**。典型数据长这样：

   ```text
   IMG_20260919_160337.jpg
       none:     14
         cw:    128
        ccw:    652   ← 选它
        180:     18
   ```

   正确方向通常是第二名的 2–5 倍，区分度很高。

4. **两道保险，避免"瞎转"**：
   - 最高分低于 60（空白页、糊了、纯图表少文字）→ **保持原样**
   - 最高分不到第二名的 1.4 倍（方向特征不明显）→ **不冒险，保持原样**

OCR 只跑在缩到 1800px 的缩略图上，单张约 1–2 秒，一次几十张照片多花一两分钟，
换来的是不用再手动检查哪张反了。

> **非 Windows 系统**：`winrt` 装不上，脚本会自动退回固定方向模式（横版图统一按
> `--rotate-ccw` 转），其余功能（排序、压缩、打包）照常可用。此时建议配合
> `--show-rotation-scores` 之外的手段人工抽查。

## 实现细节

- **排序**：优先解析文件名里的 `IMG_YYYYMMDD_HHMMSS` 时间戳，取不到才退回文件修改
  时间；时间相同时用文件名兜底，保证多次运行结果一致
- **页面尺寸**：每页短边固定为 595pt（A4 宽度），长边按图片宽高比计算，因此没有白边
- **PDF 打包**：把压缩好的 JPEG 以 `DCTDecode` 直接内嵌进 PDF（自己拼 PDF 对象，
  不依赖 reportlab / img2pdf），**不经过二次编码**，所以画质没有任何额外损失
- **灰度化**：手机拍的文档本来就是黑白的，转 8 位灰度即可；`--bw` 则进一步做二值化

## 常见问题

**Q：提示"系统没有可用的 OCR 语言包"，判方向失效了？**
按上面「环境要求」装上简体中文的 OCR 语言包即可。装不了也不影响使用，
脚本会退回固定方向模式，用 `--rotate-ccw` 指定方向。

**Q：某几张照片还是转反了怎么办？**
先用 `--show-rotation-scores` 看那张图四个方向的得分：

- 如果正确方向的分**并不高**（比如只有 30 分），说明这张图文字太少或者拍糊了，
  属于两道保险故意"不冒险"的情况，此时加参数手动指定方向即可：
  `python ocr_pdf.py --no-detect-rotation --rotate-ccw ccw`
- 如果分数看着正常却选错了，欢迎提 issue 并附上那张照片的得分，
  我会调整打分或阈值策略。

**Q：生成的 PDF 体积还是太大？**
`-q` 降到 60–65，`--max-long` 降到 1800，或者直接用 `--bw`。这三档下来通常能
再小一半以上。

**Q：处理速度慢？**
大头是 OCR（每张 1–2 秒 × 4 个方向）。如果这批照片方向本来就统一，用
`--no-detect-rotation` 可以跳过 OCR，速度会快很多。

**Q：照片里除了纸还有桌面背景，需要先裁掉吗？**
不需要。脚本不裁剪，背景会作为灰度内容保留，对阅读没有影响。如果你需要自动
裁边/去背景，那是另一个功能，本脚本不做。

**Q：会修改我的原图吗？**
不会。**全程只读原图**，所有中间结果都在内存里，输出只有一个新的 PDF 文件。
另外加 `--keep-temp` 会把中间用的 JPEG 存到 `_pdf_pages/` 供你检查。
